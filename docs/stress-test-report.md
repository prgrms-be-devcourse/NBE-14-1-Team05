# #95 주문 생성 스트레스 테스트 결과 보고서

## #️⃣ 작업 개요

대량의 주문 생성 요청이 동시에 발생하는 상황을 가정하여 주문 생성 기능에 대한 스트레스 테스트를 진행했습니다.

기존 주문 도메인 구조를 기준으로 진행했던 테스트 결과를 **Baseline 데이터**로 활용하고, 엔티티 구조 변경 후 동일한 주문 생성 작업을 다시 측정하여 변경 전후의 성능 특성을 비교했습니다.

각 테스트는 총 10,000건의 주문 생성 작업을 대상으로 진행했으며, 성공/실패 여부, 처리 시간 및 TPS(Transaction Per Second)를 측정했습니다.

> 본 테스트는 애플리케이션 내부에서 주문 생성 작업을 반복 수행하는 방식으로 진행되었으며, 실제 외부 HTTP 요청 기반의 부하 테스트 결과와는 차이가 있을 수 있습니다.

---

## #️⃣ 테스트 환경 및 조건

* **Database:** H2 Database
* **테스트 데이터:** 상품 1,000개 사전 생성
* **총 주문 요청 수:** 10,000건
* **배치당 요청 수:** 1,000건
* **측정 기준:** 주문 생성 작업의 성공/실패, 처리 시간 및 TPS
* **비교 대상:** 엔티티 구조 변경 전 / 최신 엔티티 구조 변경 후

### 측정 항목

* 성공/실패 요청 수
* 평균 처리 시간
* 최소/최대 처리 시간
* 실제 TPS
* 전체 테스트 진행 시간

## #️⃣ 테스트 결과 분석

### 1. 모든 테스트 조건에서 요청 성공률 100% 달성

엔티티 구조 변경 후 진행한 모든 테스트에서 총 10,000건의 주문 생성 작업이 실패 없이 완료되었습니다.

요청 간격을 1초부터 10ms까지 줄이는 과정에서도 실패 요청은 발생하지 않아, 본 테스트 범위 내에서 주문 생성 기능의 안정적인 처리 결과를 확인할 수 있었습니다.

### 2. 요청 부하 증가에 따라 TPS 증가

요청 간격이 짧아질수록 전체 테스트 시간이 감소하고 Actual TPS가 증가하는 모습을 확인했습니다.

* 1,000ms 간격: 약 **694 TPS**
* 500ms 간격: 약 **1,023 TPS**
* 100ms 간격: 약 **1,694 TPS**
* 10ms 간격: 최대 약 **1,932 TPS**

특히 10ms 간격 테스트에서 가장 높은 TPS를 기록했으며, 짧은 시간 동안 많은 주문 생성 작업을 처리할 수 있음을 확인했습니다.

### 3. 평균 처리 시간은 요청 간격에 따라 일정한 패턴을 보이지 않음

평균 처리 시간은 약 **142~191ms** 범위에서 측정되었습니다.

요청 간격이 짧아진다고 평균 처리 시간이 단순히 증가하는 형태는 나타나지 않았으며, 실행 환경과 JVM 상태, 데이터베이스 처리 등의 영향을 받을 수 있는 것으로 보입니다.

따라서 단일 실행 결과만으로 성능 차이를 판단하기보다는, 동일 조건에서 여러 차례 반복 측정하여 평균값을 비교하는 것이 필요합니다.

### 4. 고부하 상황에서도 안정적인 요청 처리 확인

가장 높은 부하 조건인 10ms 간격 테스트에서도 모든 요청이 성공적으로 처리되었습니다.

최대 처리 시간은 테스트 조건에 따라 최대 738ms까지 발생했지만, 전체 요청 실패 없이 테스트가 완료되었습니다.

## #️⃣ 엔티티 구조 변경 전후 비교

기존 테스트는 엔티티 구조 변경 전 주문 도메인을 기준으로 수행했으며, 이번 테스트는 최신 엔티티 구조를 반영한 상태에서 동일하게 총 10,000건의 주문 생성 작업을 수행했습니다.

두 테스트 모두 테스트 환경과 실행 방식에 따른 영향을 받을 수 있으므로 단순 수치만으로 엔티티 구조 변경 자체가 성능을 향상 또는 저하시켰다고 단정하기는 어렵습니다.

다만 이번 재측정을 통해 다음과 같은 비교 기준을 확보했습니다.

* 엔티티 구조 변경 후에도 모든 테스트 조건에서 **10,000건 요청 성공률 100% 유지**
* 최신 엔티티 구조에서도 **최대 약 1,900 TPS 수준의 주문 생성 처리량 확인**
* 평균 처리 시간은 테스트 조건에 따라 **약 142~191ms 범위**로 측정
* 엔티티 구조 변경 이후에도 고부하 조건에서 요청 실패 없이 주문 생성 가능

향후 정확한 성능 비교를 위해서는 변경 전후 코드에서 **동일한 실행 환경과 요청 조건을 유지한 반복 테스트**를 진행하고 평균값을 기준으로 비교할 필요가 있습니다.

## #️⃣ 결론

이번 테스트를 통해 **최신 엔티티 구조 변경 후 주문 생성 기능의 스트레스 테스트 결과를 확보**했습니다.

모든 테스트 조건에서 10,000건의 주문 생성 작업이 실패 없이 완료되었으며, 요청 간격이 짧아질수록 전체 처리량이 증가하는 모습을 확인했습니다.

특히 가장 높은 부하 조건인 10ms 간격에서도 약 **1,850~1,930 TPS** 수준의 처리량을 기록하며 안정적으로 테스트를 완료했습니다.

다만 본 테스트는 애플리케이션 내부에서 직접 주문 생성 로직을 호출하는 방식으로 진행되었으므로, 실제 사용자 환경에서의 성능을 측정하기 위해서는 향후 외부 HTTP 요청 기반의 부하 테스트 도구를 활용한 추가 테스트가 필요합니다.
